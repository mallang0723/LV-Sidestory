# Side Story (사이드 스토리)

Side Story는 지금 채팅을 바탕으로 외전 스토리·분석·내면(말하기·쓰기)·HTML·AU 프로필을 만들고, 본편과 따로 보관하는 Lumiverse 확장입니다. 0.2.0부터는 **SillyTavern용 원작 ST-Sidestory 0.17.0의 코드를 거의 그대로 가져와** 루미버스 호스트 어댑터 위에서 돌립니다. 원작 작가들이 마리나라판(이면 · SIDE B)을 만들 때처럼, 원작의 `src/`는 그대로 두고 호스트와 맞닿는 부분(`st-host.js`)만 루미버스용으로 바꿨습니다.

Lumiverse 공식 확장이 아니며, Lumiverse 팀이 만들거나 승인·보증·지원하는 확장이 아닙니다. 실제 모델 응답 품질은 검증하지 않았습니다.

## 쓰는 법

1. 채팅을 연 상태에서 서랍의 **Side Story** 탭을 엽니다. 현재 채팅의 캐릭터·페르소나·로어북·요약·연결을 **자동으로 불러옵니다**. 채팅을 바꾸면 그 채팅 기준으로 다시 불러옵니다(따로 누를 “자료 불러오기”는 없습니다).
2. **새로 쓰기**에서 형식(스토리·분석·HTML·말하기·쓰기·AU)을 고르고 요청을 적은 뒤 **생성하기**를 누르면 바로 생성합니다. 형식마다 예시 문구, 분량·시점·언어, 말하기의 묻는 사람·속마음 같은 원작 옵션이 그대로 있습니다. 지난 요청은 “지난 요청”에서 다시 고를 수 있습니다.
3. 보내기 전에 확인하고 싶으면 **미리보기**를 누르세요. 모델에 보내지 않고 최종 프롬프트만 만들어 *설정 › 프롬프트 내역*에 보여 줍니다(선택 기능).
4. 결과 화면에서 이어쓰기(시리즈·갈래), 다시 쓰기(고쳐 쓰기/새로 쓰기), 복제, 번역(긴 글은 나눠 번역하고 실패한 구간부터 이어서), 문단별 번역 다듬기, 원문 직접 고치기, 복사·파일·PNG 저장, 발췌 이미지, 현재 채팅에 추가를 쓸 수 있습니다.
5. **보관함**에서 이 채팅/이 캐릭터/전체 범위, 검색, 폴더·태그·즐겨찾기, 제목 바꾸기, 일괄 삭제, 백업·불러오기를 씁니다.
6. **다면(AU)**: 인물 핵심정보를 추출해 항목별로 고친 뒤 AU를 만들고, 결과를 새 캐릭터·새 페르소나로 저장할 수 있습니다.

### 참고 자료: “현재 루미버스 연결”

설정 › API 연결의 기본값 **현재 루미버스 연결**은 원작의 “현재 실리태번 연결”에 해당합니다. 루미버스가 지금 채팅에 쓰는 프리셋으로 조립한 프롬프트(캐릭터 카드·페르소나·로어북·작가 노트·채팅 기록 등)를 그대로 받아 오고(`generate.dryRun`), 그 끝에 Side Story 요청을 마지막 유저 메시지로 붙여 보냅니다. Side Story 요청 안의 `{{char}}`·`{{user}}`는 캐릭터·페르소나 이름으로 바꿉니다.

- **본편 대화**(안 넣음/최근만/전체)와 이어쓰기의 **시리즈 기준점**은 조립된 프롬프트의 채팅 기록 구간에서 해당 메시지를 빼는 방식으로 반영합니다. 앞 편은 채팅 기록 바로 뒤에 대화로 붙습니다.
- **로어북 · 루미버스 설정 따르기**: 루미버스의 로어북 활성화·키워드 설정을 그대로 씁니다. **엔트리 직접 고르기**: 여러 책을 고르고, 체크한 엔트리만(키워드 스캔 옵션 포함) Side Story 요청에 넣으며, 루미버스가 넣은 로어북 항목은 프롬프트에서 뺍니다. 로어북·엔트리 목록은 확장이 끝까지 다 읽어 오므로 페이지 버튼이 없습니다. **연결된 로어북 불러오기**는 캐릭터·페르소나·채팅·전역 로어북을 고릅니다.
- 다른 연결 프로필을 고르면 원작처럼 Side Story가 참고 자료를 직접 조립합니다(카드·요약·대화·고른 로어북).
- 원작의 “RP 프리셋 바꿔 생성” 기능은 없습니다. 루미버스에서는 항상 지금 프리셋을 따릅니다. 이전 버전(0.1.x)의 프리셋 드롭다운과 `presets` 권한도 없앴습니다.

## 설치

Lumiverse 확장 설치에서 GitHub 주소 `https://github.com/mallang0723/LV-Sidestory`를 입력하고, 아래 권한을 확인한 뒤 활성화하세요. 저장소에 실행물(`dist/`)이 들어 있어 따로 빌드할 필요는 없습니다.

### 요청하는 권한과 쓰는 곳

| 권한 | 쓰는 곳 |
|---|---|
| `generation` | 생성·번역·인물 추출(`generate.raw`), “현재 루미버스 연결”의 프롬프트 조립(`generate.dryRun`), 연결 목록 |
| `chats` | 현재 채팅 정보·Loom 요약·채팅에 연결된 로어북 읽기 |
| `chat_mutation` | 본편 대화 읽기(참고 자료·시리즈 기준점·키워드 스캔), **“현재 채팅에 추가”를 누를 때만** 메시지 추가. 본편 메시지를 고치거나 지우지 않습니다 |
| `characters` | 참고할 캐릭터 카드 읽기, AU 결과를 **“새 캐릭터로 저장”** 할 때 만들기 |
| `personas` | 현재 페르소나 읽기, AU 결과를 **“새 페르소나로 저장”** 할 때 만들기 |
| `world_books` | 로어북·엔트리 목록과 전역/연결 로어북 읽기. 로어북을 고치지 않습니다 |

토큰 수 세기와 확장 저장 공간은 별도 권한이 필요 없습니다. 프리셋 권한(`presets`)은 요청하지 않습니다.

### 저장 위치와 외부 요청

- 보관함(아티클)과 설정은 루미버스 서버의 이 확장 사용자 저장 공간(`archive/`, `sidestory-settings.json`)에 저장되어 휴대폰·PC에서 같이 보입니다. 원작과 같은 레코드 구조라 원작 백업 파일(`st-sidestory-backup`)을 그대로 불러올 수 있습니다.
- 발췌 이미지 배경과 최근 요청 5개(프롬프트 내역)는 원작처럼 지금 쓰는 브라우저에만 남습니다.
- 원작과 같이 읽기 글꼴 “프리텐다드”를 jsDelivr CDN에서 받습니다. 읽기 설정에서 다른 글꼴을 고르면 받지 않습니다. 그 밖의 외부 요청은 루미버스 연결로 보내는 모델 요청뿐입니다.

### 0.1.x에서 올리는 경우

처음 열 때 0.1.x가 `records/`에 남긴 결과를 새 보관함으로 **자동으로 옮깁니다**(한 번만). 원래 파일은 지우지 않습니다.

- 분석·스토리·내면 말하기·쓰기 → 같은 형식, 핵심정보 → 다면(AU)의 인물 추출본, AU 결과 → 다면 결과, 정적 HTML → HTML 아티클.
- 편집본은 원본의 “직접 고친 버전”으로 이어지고, 원작 백업에서 가져왔던 결과는 원작 레코드(폴더·태그·시리즈 포함)를 그대로 되살립니다.
- 문단 번역은 원작의 번역 보기로 옮깁니다. HTML 결과의 번역은 원작 방식과 달라 표시하지 않고 기록(`lvLegacy`)에만 남깁니다.
- 0.1.x의 프리셋 선택값은 쓰지 않습니다.

## 할 수 없는 것

- **이 아티클로 새 채팅 시작**: Spindle에 새 채팅을 만드는 API가 없어 메뉴에서 뺐습니다. 새 채팅을 연 뒤 “복사”한 본문을 붙여 넣어 주세요.
- **RP 프리셋을 잠깐 바꿔 생성**: 원작의 실리태번 전용 기능이라 없습니다.
- “엔트리 직접 고르기”에서 루미버스 로어북을 빼는 것은 조립된 프롬프트에서 같은 내용을 찾아 지우는 방식입니다. 다른 블록에 섞여 내용이 바뀐 항목은 남을 수 있습니다(프롬프트 내역의 연결 정보에 지운/못 찾은 수가 나옵니다).
- 원작이 늘린 응답 길이만큼 컨텍스트를 넓히는 처리는 없습니다. 루미버스 프리셋의 컨텍스트 한도로 조립된 프롬프트에 Side Story의 최대 출력이 더해집니다.
- “현재 채팅에 추가”한 메시지는 Spindle 규칙에 따라 assistant 메시지로 붙습니다(이름 표시는 루미버스가 정합니다).
- AU를 새 캐릭터로 저장할 때 원본 이미지는 복사하지 않습니다.

## 빌드와 검증

- 원작 소스는 `upstream/`에 고정 커밋 그대로 있습니다. `npm run build`가 원작의 `build.py`와 같은 순서로 묶어 `src/generated/side-story-app.js`를 만들고(Bun 번들 → `dist/`), 원작 파일에 대한 변경은 `src/lumiverse/patches.mjs`의 표로만 합니다(기준 문자열이 달라지면 빌드가 멈춥니다). 화면 폭 조건은 서랍 폭 기준(컨테이너 쿼리)으로 바꾸고, 휴대폰·좁은 서랍에서는 글자 15px(보조 13px)·누름 영역 44px 이상이 되도록 원작의 작은 크기를 덧씌웁니다(`src/lumiverse/css-floor.mjs`). Bun 경로는 `BUN_BIN`으로 지정합니다.
- `npm test`: 가짜 Spindle API로 어댑터(드라이런 조립·페이지 읽기·채팅 전환·모델 전달·미리보기), 0.1.x 이전, 빌드 무결성을 검사합니다.
- `npm run qa:browser`: headless Chromium에서 서랍 대역 페이지에 실행물을 띄워 360×460·390×844·1280×800 화면에서 넘침·글자 크기·누름 영역을 검사하고 `qa/screens/v020/`에 스크린샷을 남깁니다. 실제 모델 호출은 하지 않습니다.
- `npm run qa:scroll`: Playwright로 Firefox·Chromium 휴대폰 화면에서 각 화면과 아티클이 휠·터치로 스크롤되는지 검사합니다(`PLAYWRIGHT_MODULE`, `FIREFOX_BIN`으로 지정).

자세한 검증 범위는 [QA.md](QA.md), 변경 내역은 [CHANGELOG.md](CHANGELOG.md)를 보세요.
